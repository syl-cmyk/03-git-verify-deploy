**什么是快照（snapshot）**

一次 commit 存的不是「这次改了哪几行」，而是那一刻你所有被跟踪文件的完整状态，相当于给整个项目文件夹拍了一张照片。

- 你可以回到任何一个 commit，把当时每个文件的内容原样取回来。
- Git 展示的「改动」（diff）是它拿两张快照对比算出来的，但它真正存下来的是每一版的完整内容。
- 底层为了省空间，没变的文件会复用，不会真的存很多份，但你可以就把每个 commit 理解成「整个项目的一张完整照片」。

**分支也不是「待工作区」**。你说的待工作区是暂存区(staging area,`git add` 放东西的地方),那是「下一次提交要打包哪些改动」的托盘。分支管的是「我的提交落在哪条历史线上」。两回事。

# Lab - start a copy, check that it is done

A lab is the hands-on part of a lecture: `class/NN-<slug>/lab.md` says what to do and ends in one "Done when" sentence, `class/NN-<slug>/lab/starter/` holds the files to start from, and `check.py` among them verifies that sentence.
The student works on a copy in `work/NN/lab`, their own space inside this repo, never on the course files.
This skill makes the copy and runs the check.
The lab itself happens between the student and you in that copy, per `lab.md`: they ask, you build and explain; this skill never runs ahead of them.

## Resolve the lecture and the copy

- The lecture is the number given (`/lab start 02`, "the 02 lab"); without one, it is the most recent lecture whose date in `SCHEDULE.md` is today or earlier and whose folder has `class/NN-*/lab.md`, and, if no such lecture has met yet, the earliest released one that has it.
  For a check, prefer the lab whose section in the Labs part of `progress.local.md` has `Copied out` ticked and `Done` still open.
  If no released lecture has a `lab.md`, say so and stop; a number the student gave for an unreleased lecture, or one without `lab.md`, gets the same plain answer.
- Read `lab.md` for the "Done when" sentence and for whether the lab ends in a push (it contains the sentence "This lab ends in a push to your own GitHub repository.").
- The copy is `work/NN/lab` at the root of this repo: one folder per lecture number under `work/`, with the lab inside it (the same lecture's demo replay goes in `work/NN/demo`).
  `work/` is gitignored, so the course repo never sees what is in it, and a lab copy can be its own git repository.
- `/lab NN` with no verb means check when the copy exists and start when it does not; say which one you did, in a few words, so the student knows.
- Everything this skill writes goes into that copy or into `progress.local.md`; the write guard allows both, and nothing else in this repo is ever touched.

## /lab start [NN]

1. If the copy already exists and has files in it, overwrite nothing: say so and offer `/lab check` instead.
2. Create the copy folder and copy every file in `lab/starter/` into it, `check.py` included (`mkdir -p work/NN/lab` and `cp -R class/NN-<slug>/lab/starter/. work/NN/lab`; Git Bash on Windows has both).
3. If the lab ends in a push, run `git init -b main` in the copy (so the branch is `main`, which the labs assume) and make a first commit of the starter files: `git add .`, then `git commit -m "Start the NN lab"`.
   If git refuses because no name or email is set, show the two `git config --global` lines from `setup.md`, let the student run them, and try again.
   A lab that does not end in a push skips this step.
4. Run `python3 check.py` in the copy (Windows: `python check.py`) and show every PASS and FAIL line verbatim, always: the FAIL lines are the student's task list, and a reply that skips them leaves the student without one.
   Say in one line that the passing lines are what the starter already does and that the failing lines are the task.
5. In `progress.local.md`, following the `progress` skill's file rules, make sure the Labs part has this lab's section (create the part or the section if needed) and tick `Copied out to work/NN/lab` with today's date.
6. Then give the instructions, so the student knows what the lab is before they start: the steps of `lab.md` in order, one line each, in `lab.md`'s own words and with its numbering (for 02: run it first, then the three steps under "Your task"; for 03: the ten steps), the budget when `lab.md` states one, and the "Done when" sentence.
   Keep it to what `lab.md` says; the details of each step come when the student reaches it.
7. Hand over with an invitation: the student stays in this session and says what they want done next, and you work in `work/NN/lab`.
   Name the first step as the natural place to begin ("Would you like to start with step 1, where I explain what converter.py does?"), and do not start on it yourself; the first move is theirs.

## /lab check [NN]

1. Find the copy as above.
   If the folder is missing, ask in one question where the copy is, use that path, and record it in the `Copied out to <path>` line; if there is no copy at all, offer `/lab start`.
2. If the copy has no `check.py` (it was copied before the file existed), copy it there from `lab/starter/check.py` and say so.
3. Run `python3 check.py` in the copy (Windows: `python check.py`) and show every PASS and FAIL line verbatim.
4. All passed (exit code 0, last line `All checks passed.`): tick the lab's `Done` line in `progress.local.md` with today's date and say the lab is done.
   This is also how the student proves the lab before class ends: a passing `/lab check` on their screen.
5. Anything failed: that is the normal state in the middle of a lab, so treat it that way, in the voice `CLAUDE.md` asks for.
   For each FAIL line, say in plain words what the lab still needs, defining each term in one clause, and point at the exact step in `lab.md` that covers it ("that is step 2 under Your task in lab.md").
   Then offer to do that step together, as an invitation, and ask for the one thing only the student can decide, when there is one: for 02, which conversion they actually use; for 03, the sentence that replaces the placeholder.
   When they answer, build it with them in the copy, narrating each change, then run the check again so they see the line turn to PASS.
   A push that asked for a password means the GitHub CLI sign-in from `setup.md` step 4 (`gh auth login`); point there.
   The check itself changes nothing, and never start a step the student has not agreed to.
6. Never tick `Done` without a passing run in this session: not on "I finished it", not on a run that mostly passed, not on yesterday's run.
   "I finished the 02 lab" means run `/lab check 02`, and the result decides.

## Rules for both

- The check is read-only and offline and needs only Python 3 and git; if `python3` or `git` is missing, point at `setup.md` and stop.
- The checklist is a private aid, not a grade; Canvas is the record.
- Course files are never written; the copy in `work/NN/lab` is edited only when the student asks for a lab step, never by the check.
